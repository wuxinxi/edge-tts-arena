# 评测、统计与记录

[返回 README](../README.md) · [模型准备](models.md)

平台当前测量的是冷启动离线工作流。模型之间的比较需要同时保留文本、参考、音色、版本、设备、精度、速度方式和实际参数。

## 配置与场景

统一条件使用相同目标文本和基础预设，关闭 ChatTTS 对话润色，Qwen 1.7B 不附加风格指令。推荐配置使用 Qwen 清晰播报、CosyVoice 温暖讲述、ChatTTS 自然对话，其余基础预设。所有模式以模型速度 1.0 生成，再统一处理输出速度。

需要参考的模型使用同一份参考及原文；预置音色模型不使用参考。统一输入不代表算法、音色和原生能力完全一样，推荐结果不能混入基础配置排名。

自定义文本与场景测试集二选一。测试集含短提示、长段落、数字日期、多音字、中英混读和情绪对话。结果按场景分别查看，避免把不同长度的文本混合排名。

## 指标计算

| 字段 | 实际计算 |
| --- | --- |
| `elapsed_time_sec` | worker 启动、加载、生成及选用的输出变速期间的总时间；最终输出保存与排队不在范围内 |
| `audio_duration_sec` | 最终 WAV 的时长 |
| `rtf` | 未四舍五入的耗时 / 实际最终时长，之后保留三位小数 |
| `memory_peak_mb` | 后端与其子进程 RSS 总和的最大采样值 |
| `memory_diff_mb` | `max(0, memory_peak_mb - 运行前 RSS 基线)` |
| `memory_used_mb` | 最后一次采样的进程树 RSS，不是峰值 |
| `ttfb_ms` | 当前未测流式首包，返回 `null` |

RSS 每 50ms 采样，MB 字段以字节 / 1024² 计算，可能漏过短时峰值；它不等于完整显存或 MPS 内存。同一共享内存页也可能在不同进程 RSS 中重复出现，不宜把它当作系统实际新增物理内存。峰值与增量分别反映运行期间的进程开销和相对基线的变化，不是主权重文件大小。

RTF 小于 1 仅表示本次离线生成耗时小于输出音频时长，不能证明流式首包、持续供音或对话交互已达标。当前未测模型常驻后的稳态速度。

## 重复统计与图表

每个场景按模型汇总成功 / 已返回次数、耗时中位数和范围、RTF 中位数、RSS 增量中位数。API 支持 1–5 次重复，界面提供 1 / 2 / 3 / 5 次。默认种子固定，因此重复测量主要观察运行波动，不测不同随机种子的质量稳定性。

- 失败不进入资源指标统计，缺失指标不填零。
- 已返回的失败项计入成功率分母；排队、未运行和未返回项不计入。
- 只有一次测量时不能据此讨论波动，多次测量的范围也不等于长期可靠性。
- 人工试听结果单独保存，不加入性能统计或自动改写生成状态。

默认柱状图从零开始，按所选指标中位数从低到高排列。曲线横轴按模型参数量排列，连接模型点仅辅助比较，不表示时间趋势。

性能雷达最多叠加四款具备完整指标的模型，四轴为 RTF、耗时、内存峰值、内存增量。相对值为「本轮最低值 / 当前值 × 100」，零值按实现的边界规则处理；越向外表示该项相对代价越低。参考集合为本轮场景中具有完整指标的成功模型，随结果到达可能变化。

这些轴存在相关性，雷达面积不能作为综合能力或音质分。原始数据与单位始终是判断依据。

## 批次状态与操作

任务按「模型 × 文本 × 次数」串行执行，平台与 CLI 共用推理锁。进度表示已经返回结果的任务比例，不是模型内部推理百分比，不预测剩余时间。准备失败时未运行项不伪装成已完成。

停止仅阻止后续任务，当前生成会正常结束并保存。未运行项不算失败；停止最后一项时，如果它已在运行，完成后批次仍可记为已结束。重试只针对原失败项，创建关联的新批次，保留原样本与次数，不覆盖旧结果，也不把未运行项作为失败项重试。

上传参考只在原任务生命周期内临时保存。重试或恢复设置时需要重新上传，或明确选择默认参考；两者的实际参考条件应在结果中分别判断。

刷新页面会尝试恢复该浏览器的活动任务；网络失败时重连。服务重启读取已有快照，未结束任务标为中断，不自动继续推理。查看历史结果不改待运行计划，点击「使用这些条件」才恢复配置。

## 人工试听与保存

同场景可选不同模型或不同轮次 A/B 试听，播放一边会暂停另一边。记录包括场景可用性、自然度、表达和漏字、重复、提前结束、异常发音、杂音等问题，默认均为尚未判断。未勾选异常不表示已确认正确。

程序只做有效音频及保守的过短检查，不能根据非静音波形推断正文正确。固定种子不能保证跨设备或版本字节一致，也不等于生成质量稳定。

保存试听会独立写入 `.review.json`，不修改音频和原参数。会话中未保存草稿可跨页面继续编辑，刷新或关闭前仍需保存。已有文件损坏或无法读取时返回错误并阻止覆盖；历史与导出附带读取错误，不伪装成没有评价。

## 历史分页与回收站

两类历史均支持页码、总数和每页数量，界面可选 5 / 10 / 20 / 50 条。删除末页最后一条后返回有效页，回收站可恢复。

- **批次历史**：删除状态保存于批次快照，删除后批次查询与导出不可用，恢复后可再次查看。运行中或排队中的批次不能删除。
- **生成历史**：删除状态独立保存在 `outputs/.run-history/`，仅隐藏该历史列表中的记录，原音频、参数导出、试听记录与所属批次仍可用。

两者均保留原音频、参数和试听文件，不提供永久清空。管理文件异常会报错，原子写入失败不改变原状态。

## 批次 API

浏览器界面可完成日常操作，完整交互文档位于运行服务的 `/docs`。下面的请求会启动**真实生成**，不会下载缺失模型；需先确认指定模型已就绪。

```bash
curl -X POST http://127.0.0.1:8081/api/tts/compare/jobs \
  -H 'Content-Type: application/json' \
  -d '{
    "model_keys": ["kokoro-82m", "melotts-zh"],
    "text": "欢迎使用语音助手。您的订单预计明天下午三点送达，请留意通知。",
    "benchmark_mode": "uniform",
    "speed": 1.0,
    "speed_mode": "output",
    "repeats": 2
  }'
```

接口返回 202 和 `data.job_id`，随后查询 `GET /api/tts/compare/jobs/{job_id}`。同步的 `POST /api/tts/compare` 也保留，但不提供异步进度。

| 操作 | 接口 |
| --- | --- |
| 硬件 / 模型状态 | `GET /api/system`、`GET /api/models` |
| 单模型生成 | `POST /api/tts/generate` |
| 默认参考 | `GET /api/reference/default` |
| 停止后续生成 | `POST /api/tts/compare/jobs/{job_id}/stop` |
| 重试失败项 | `POST /api/comparisons/{job_id}/retry` |
| 批次分页 | `GET /api/comparisons?page=1&limit=5&deleted=false` |
| 删除 / 恢复批次 | `DELETE /api/comparisons/{job_id}`、`POST /api/comparisons/{job_id}/restore` |
| 完整批次导出 | `GET /api/comparisons/{job_id}/export` |
| 生成历史分页 | `GET /api/runs?page=1&limit=5&deleted=false` |
| 删除 / 恢复生成历史 | `DELETE /api/runs/{filename}`、`POST /api/runs/{filename}/restore` |
| 参数导出 | `GET /api/runs/{filename}` |
| 试听记录读 / 写 | `GET /api/runs/{filename}/review`、`PUT /api/runs/{filename}/review` |
| 原音频 | `GET /api/audio/{filename}` |

生成记录接口的 `filename` 为完整 `.run.json` 文件名，例如 `qwen3-tts-1.7b_abcd1234.run.json`；音频接口使用 `.wav` 文件名。分页保持 `data` 数组，另返回 `pagination`，包括 `total`、`page`、`page_size`、`pages`。`deleted=true` 查询对应回收站。

单模型生成的 `ref_audio` 接受 Base64 / data URL，`ref_text` 为配套原文；批次请求同样支持这两个字段。使用测试集时通过 `samples` 提交实际文本，具体校验和字段以 `/docs` 为准。
